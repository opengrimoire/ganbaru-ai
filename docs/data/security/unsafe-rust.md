# Unsafe Rust

Unsafe Rust is exceptional in Ganbaru AI. It is allowed only at a reviewed native, foreign-function, or operating-system boundary whose required behavior cannot currently be preserved with safe Rust. The [`unsafe` keyword](https://doc.rust-lang.org/stable/reference/unsafe-keyword.html) creates proof obligations that the compiler does not check. Calling an upstream function marked `unsafe` does not transfer those obligations to the upstream project. Ganbaru AI remains responsible for the arguments, ownership, lifetime, aliasing, thread, callback, and cleanup invariants at every call.

## Scope and dependency separation

This page covers tracked, repository-owned Rust, including libraries, binaries, platform-gated modules, tests, examples, build scripts, and tracked generated Rust. It covers unsafe blocks and functions, unsafe traits and implementations, external blocks, unsafe attributes, assembly, raw-pointer operations, and unsafe code emitted by repository-owned macros.

Dependency-owned unsafe code, RustSec findings, transitive unsoundness, and audit exceptions are separate concerns. They are recorded in [Dependency audits](dependency-audits.md). A clean dependency audit does not prove first-party unsafe code sound, and a first-party unsafe review does not prove dependency code sound.

The repository review on 2026-08-30 found no first-party unsafe code in build scripts, Rust examples, tracked generated Rust, or `ganbaru-native-messaging`. It also found no unsafe traits or implementations, unsafe attributes, inline assembly, or repository macros that emit unsafe code. The retained boundaries are grouped below by external contract. Expression counts are intentionally omitted because extracting a wrapper can change a count without changing the security boundary.

## Policy

- Prefer a safe standard-library, workspace, or already-approved upstream API when it preserves the same behavior and security properties. Do not replace descriptor-relative, no-follow, atomic, or process-tree behavior with a weaker path-based or single-process operation merely to remove `unsafe`.
- Keep each unsafe operation in the smallest practical private wrapper. The wrapper must expose a safe interface only when all unchecked requirements are established internally. A public `unsafe fn` requires rustdoc with a `# Safety` section and an explicit reason that a safe interface is impossible.
- Put an immediate `// SAFETY:` comment on every unsafe block or operation. The comment must state the concrete local proof, such as pointer validity and alignment, initialized output, buffer capacity, handle ownership, callback lifetime, thread affinity, or balanced cleanup. Restating an API name or saying that a call was reviewed is insufficient.
- Declare every foreign block as `unsafe extern` with the exact ABI and signatures from the authoritative native headers. This is required even where the crate edition would accept the older spelling. The [Rust Reference](https://doc.rust-lang.org/stable/reference/items/external-blocks.html) explains why declaration correctness is itself an unsafe obligation.
- Check null pointers, invalid handles, return codes, initialized lengths, integer conversions, and operating-system sentinel values before constructing a Rust reference or owned value. Transfer native ownership exactly once and prefer RAII types such as `File`, `OwnedFd`, and `OwnedHandle`.
- Foreign callbacks must not unwind across the ABI boundary. Their captured state must outlive registration, shared state must obey synchronization rules, and unregistration must happen before the last referenced allocation is released.
- Treat platform documentation as part of the proof. Pin or review upstream versions when an invariant depends on Tauri, Wry, `windows`, `objc2`, SQLx, libc, or another binding's representation or callback behavior.
- Add focused tests for the safe wrapper's success, failure, cleanup, and race-sensitive behavior. Tests support a proof but do not replace one. Platform-gated boundaries require compilation and relevant validation on the owning target.
- Update this inventory when adding, removing, or materially changing a boundary. Record the safe replacement trigger so temporary native workarounds do not become permanent by accident.

The three libraries that currently own retained boundaries, `ganbaru-tauri-app`, `ganbaru-chat`, and `ganbaru-chat-providers`, deny `clippy::undocumented_unsafe_blocks` and `unsafe_op_in_unsafe_fn`. These lints enforce useful local structure but do not establish that a safety proof is correct.

## Review method

An unsafe review must combine structural inventory and manual contract analysis:

1. Enumerate every tracked `.rs` file, including tests, examples, build scripts, and generated sources.
2. Search case-insensitively for unsafe syntax and related operations. Include split token forms, `extern` blocks without `unsafe`, callback types, unsafe attributes, raw pointer creation or dereference, `MaybeUninit`, `from_raw` ownership transfers, inline assembly, FFI declarations, and macro input that can produce unsafe tokens.
3. Classify comments, strings, fixtures, generated data, and dependency paths separately from executable first-party code.
4. Read the complete control flow around each result, error path, callback, ownership transfer, and destructor. Review safe callers too, because a safe wrapper must not permit invalid inputs.
5. Compare the code with primary Rust, operating-system, library, and framework contracts. Classify each mechanism as removed, retained, or replaceable when a named upstream capability becomes stable.

## Retained boundary inventory

### Descriptor-relative Unix filesystem operations

**Owned modules:** `crates/ganbaru-chat/src/chat/workspace_files/platform/unix.rs` and `apps/client/src-tauri/app/src/chat/execution_environment.rs`.

**Contract and disposition:** These modules use the POSIX [`openat`](https://pubs.opengroup.org/onlinepubs/9799919799/functions/open.html), directory-stream, metadata, unlink, and rename families to keep authorization relative to already-open directory descriptors. The workspace file service also uses Linux, Android, and Apple atomic no-replace and exchange extensions. Android invokes the `renameat2` kernel operation directly because the bionic libc symbol is newer than the application's minimum API level. A missing or unsupported kernel operation produces the native error and the mutation fails closed. The service never falls back to a weaker path-based sequence. The boundary is retained because stable `std` does not expose equivalent descriptor-relative traversal, no-follow inspection, and atomic replacement semantics. Replacing it with path prechecks would restore symlink and rename races.

**Safety invariants:** Every name is one validated relative component with no NUL, separator, absolute form, `.` or `..`. Parent descriptors remain live for calls. Creation mode is supplied exactly when creation flags require it. A successful descriptor is transferred to one Rust owner and closed once. `fdopendir` receives an owned duplicate; the directory stream remains exclusive; each `readdir` name is copied before the next call; on Linux, Android, and Apple targets the documented errno location distinguishes end of stream from failure. Other Unix targets fail directory-stream completion as unsupported instead of guessing a C runtime ABI. Uninitialized output is assumed initialized only after a successful native call. After exchange, the installed entry must have the prepared file's device and inode identity plus the intended content revision, while the displaced entry must have the original identity and expected revision. Only the verified displaced entry supplies restored permissions and is eligible for a rollback attempt at verification time.

**Current residual:** Working-folder and managed-worktree authorization verify filesystem identity before the file service later opens the stored canonical root path. The service does not yet carry that original root handle as a capability or revalidate the newly opened root against the authorized identity. A same-user replacement with another physical directory can cross that interval even though component traversal after the root opens remains descriptor-relative and no-follow. A future authorization boundary should carry the opened root or revalidate its identity before each operation. After a newly created file or temporary artifact becomes visible by name, failure cleanup preserves it and returns a recovery error instead of unlinking an identity-uncertain name. Rollback remains path-based after the verifying handle closes. Another same-user writer can substitute or modify the displaced name before the exchange; the operation then returns a recovery error and preserves the resulting uncertain artifact, but it cannot guarantee which exact object occupies each name. Successful cleanup has a narrower destructive interval: substitution or modification between verification and `unlinkat` can delete that later object and still report success. The operating system does not provide a portable conditional unlink or compare-and-swap for the complete sequence. A stronger design needs an exact-object deletion capability or a serialized directory owner.

**Replacement trigger:** Replace this boundary only when stable Rust or an already-approved safe dependency provides the same descriptor-relative, no-follow, metadata, and atomic replacement guarantees on supported Unix targets.

**Required validation:** Exercise normal and error end-of-directory results, repeated open and drop, non-UTF-8 names, symlinks, special files, parent replacement races, stale revisions, permission preservation, atomic rollback, and the Linux, Android, and Apple rename variants on their owning targets. Android validation must use the declared minimum API level so no newer bionic symbol enters the load contract, and must cover `ENOSYS` or an unsupported-kernel equivalent without weakening the operation.

### Windows filesystem identity and atomic replacement

**Owned modules:** `crates/ganbaru-chat/src/chat/workspace.rs`, `crates/ganbaru-chat/src/chat/workspace_files/platform/windows.rs`, and `apps/client/src-tauri/app/src/chat/execution_environment.rs`.

**Contract and disposition:** These modules use [`GetFileInformationByHandle`](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfileinformationbyhandle) for stable directory identity, [`GetFileInformationByHandleEx`](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getfileinformationbyhandleex) for full file identity, [`ReplaceFileW`](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew) for atomic replacement, and [`MoveFileExW`](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw) without replacement flags for fail-closed moves. Private backup and recovery names use the operating system's preferred [`BCryptGenRandom`](https://learn.microsoft.com/en-us/windows/win32/api/bcrypt/nf-bcrypt-bcryptgenrandom) source. The boundary is retained while Rust's safe by-handle metadata support remains [unstable](https://github.com/rust-lang/rust/issues/63010) and no safe standard operation preserves the replacement contract.

**Safety invariants:** The owning `File` keeps every borrowed handle live. Invalid handles and unsuccessful output initialization are rejected. Current persisted identity uses the volume serial number and 64-bit file index returned by [`BY_HANDLE_FILE_INFORMATION`](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/ns-fileapi-by_handle_file_information), separated by the owning authorization domain. Atomic replacement captures the full 128-bit [`FILE_ID_INFO`](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_id_info) identity and content revision through the same opened handle for each original, prepared, installed, or displaced file it verifies. Success requires the installed target to be the prepared object with the intended revision and the backup to be the expected original. Reparse points are rejected where a managed directory must be physical. UTF-16 path buffers reject interior NUL, are terminated, and remain live for each synchronous call. `MoveFileExW` receives zero flags, so an existing destination causes failure instead of replacement. Each `ReplaceFileW` backup name contains an independently generated 256-bit system-random token that is not exposed in an earlier artifact name, and native RNG failure is checked before the destructive replacement or rollback call. Replacement, backup, and temporary files remain inside the validated parent, and every documented partial-success result is handled without treating an uncertain state as a successful commit.

**Current residual and replacement trigger:** Microsoft does not guarantee that the legacy 64-bit file index is unique on ReFS, which exposes a 128-bit identifier through `FILE_ID_INFO`. Directly changing formats would invalidate both persisted working-folder identities and Git storage identities because their hashes are unversioned and compared strictly. ReFS working-folder identity remains awaiting correction and must not be described as fully supported until a controlled, versioned migration or explicit rebind contract exists. Working-folder and managed-worktree authorization are separate from later path-based parent opens. Open ancestor handles prevent some deletion and sharing changes, but they do not turn descendant path opens into handle-relative traversal. A same-user physical replacement can therefore cross that interval. `ReplaceFileW` is path-based, so expected-revision validation and replacement are not an atomic compare-and-swap against another same-user writer. Failure and rollback paths preserve identity-uncertain target, temporary, backup, and recovery artifacts instead of deleting bytes that may belong to that writer. Successful delete and replacement cleanup still have a narrow window in which another same-user writer can substitute the verified name or modify the verified object before deletion. A fully race-free Windows compare-and-swap needs an exact-object deletion capability or a serialized directory owner. Separately adopt stable by-handle metadata and a safe atomic replacement API when they provide the required identity width, reparse-point behavior, and failure semantics.

**Required validation:** On Windows, cover current NTFS identity stability, distinct authorization domains, reparse rejection, interior-NUL rejection, replacement success, expected-content verification, partial failures, rollback, native RNG failure, preexisting generated-name collisions, and no-replace moves when the destination exists. A future `FILE_ID_INFO` migration must cover ReFS plus legacy binding or rebind behavior before ReFS continuity is claimed.

### Provider process trees and native process probes

**Owned modules:** `crates/ganbaru-chat-providers/src/chat/process.rs`, `crates/ganbaru-chat-providers/src/chat/providers/opencode/tests.rs`, `apps/client/src-tauri/app/src/chat/tests/process.rs`, and `apps/client/src-tauri/app/src/chat/tests/process_windows.rs`.

**Contract and disposition:** Unix providers use POSIX [`kill`](https://pubs.opengroup.org/onlinepubs/9799919799/functions/kill.html) with a negative process-group identifier. Windows providers use [job objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects), suspended process creation, and Tool Help thread enumeration. Test probes use native liveness operations so they can verify descendants, not only a leader process. These boundaries are retained while the relevant Unix process-group methods remain [unstable](https://github.com/rust-lang/rust/issues/141975) and stable Windows `Child` access does not expose the required [main-thread handle](https://github.com/rust-lang/rust/issues/96723).

**Safety invariants:** A Unix process-group identifier is greater than one and representable before negation, and only a fixed signal allowlist can reach the native wrapper. Zero and the broad `-1` target can never reach `kill`. `ESRCH` is an idempotent stopped result, while `EPERM` in the Unix test liveness probe means the process still exists. A numeric process-group identifier is not an owned kernel capability; after an empty group is reaped, a narrow identifier-reuse race remains a lifecycle limitation. On Windows, the child stays suspended until assignment to an owned job configured to terminate descendants on close. Native handles are checked, transferred to one RAII owner, and never closed manually after transfer. Tool Help structures carry the required size, enumeration selects the intended process, and the opened thread handle is revalidated against the child process before `ResumeThread` must report the expected prior suspension count. The Windows test probe distinguishes timeout, exit, failed waits, and unexpected statuses. These probes are test assertions, not production process capabilities.

**Replacement trigger:** Use stable standard-library process-group signaling, process-tree termination, and main-thread ownership APIs once they preserve the current descendant and cleanup guarantees.

**Required validation:** A Unix fixture must start a real descendant, stop the process group, and poll the group to `ESRCH`. Windows validation must prove that closing or terminating the job stops a descendant and must cover Tool Help and resume error classifications. Probe helpers must cover permission-denied and failed-wait results.

### Windows desktop integration

**Owned modules:** `apps/client/src-tauri/app/src/desktop_runtime.rs`, `apps/client/src-tauri/app/src/doomscrolling/foreground/windows.rs`, `apps/client/src-tauri/app/src/media_controls/windows.rs`, `apps/client/src-tauri/app/src/notification.rs`, `apps/client/src-tauri/app/src/notification/idle.rs`, and the Windows portion of `apps/client/src-tauri/app/src/pomodoro_enforcement.rs`.

**Contract and disposition:** The desktop app uses Win32 process enumeration and memory queries, foreground-window and process inspection, close messages, low-level keyboard hooks, execution-state and idle APIs, and the system media transport controls window interop API. The bindings remain unsafe even when an individual call takes no raw buffer. The boundary is retained because Tauri and stable Rust do not expose these product capabilities with the same semantics. Primary contracts include [Tool Help snapshots](https://learn.microsoft.com/en-us/windows/win32/api/tlhelp32/nf-tlhelp32-createtoolhelp32snapshot), [`LowLevelKeyboardProc`](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc), [`SetWindowsHookExW`](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowshookexw), [`GetLastInputInfo`](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getlastinputinfo), and [SMTC `GetForWindow`](https://learn.microsoft.com/en-us/windows/win32/api/systemmediatransportcontrolsinterop/nf-systemmediatransportcontrolsinterop-isystemmediatransportcontrolsinterop-getforwindow).

**Safety invariants:** Handles and output structures are initialized, validated, and RAII-owned. Buffer lengths match their allocations, and return values determine which output fields may be read. An authorized foreground `HWND` and process identity are revalidated immediately before a close request, while callers still treat the final check and message as a non-atomic operating-system boundary. The keyboard callback accepts only documented event layouts, never unwinds, returns promptly, derives modifier transitions from the hook event stream, and always delegates unhandled events. The low-level hook is delivered back to its installing thread instead of being injected into target processes. Installation identifies the current loaded application image containing the callback, surfaces rejection, pumps the required message queue, and cannot leave the hook thread blocked forever after stop is requested. Overlay creation, state changes, monitor reconciliation, replacement, close, and shutdown participate in one lifecycle barrier. The reconciler skips an interval instead of waiting when another lifecycle operation owns the barrier, while close signals and joins the worker before destroying windows or releasing native enforcement. Commands that wait for main-thread work execute off the UI thread. Normal process exit is delayed until off-main overlay cleanup completes, restart cleans before issuing its nonpreventable Tauri restart request, and shutdown intent rejects queued overlay creation. System media transport callback bodies are inside an unwind barrier. A caught panic payload is intentionally leaked because its destructor can also panic and must not restart unwinding through the non-unwind COM thunk. Power requests and media objects have balanced lifetimes. Idle-query failure is an unavailable reading, not proof of recent activity.

**Replacement trigger:** Move each operation to a safe Tauri, standard-library, or `windows` wrapper when it provides equivalent ownership, callback, and failure behavior.

**Required validation:** Compile and test this code on Windows. Cover structure initialization and failed calls, process sampling cleanup, foreground identity changes, keyboard modifier transitions and blocked chords, hook shutdown, idle failure, balanced execution state, SMTC creation for valid and stale windows, callback panics including panic-on-drop payloads, overlapping lifecycle operations, an in-flight reconciliation during close, and active-overlay process exit and restart.

### Native webview and window bridges

**Owned modules:** `apps/client/src-tauri/app/src/chat/preview/capture.rs` and the macOS window portion of `apps/client/src-tauri/app/src/pomodoro_enforcement.rs`.

**Contract and disposition:** Tauri's [`with_webview`](https://docs.rs/tauri/latest/tauri/webview/struct.Webview.html#method.with_webview) supplies a platform handle on the main thread, but Windows WebView2 capture and macOS WebKit capture still cross native COM or Objective-C interfaces. The implementation follows WebView2 [`CapturePreview`](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2?view=webview2-1.0.1462.37) and WebKit [`takeSnapshot`](https://developer.apple.com/documentation/webkit/wkwebview/takesnapshot%28with%3Acompletionhandler%3A%29). Linux capture uses WebKitGTK's safe Rust method, but that dependency also invokes Ganbaru's completion closure through a foreign non-unwind trampoline. The Linux closure therefore shares the callback-containment policy even though it adds no first-party unsafe block. The boundary is retained because Tauri and Wry do not currently expose a safe portable capture API or typed native-window operation for these uses.

**Safety invariants:** Native objects are non-null, of the expected interface or class, live for every synchronous use, and retained for asynchronous callbacks where required. Calls stay on the framework-required main thread. COM streams are owned, bounded before allocation, rewound before reading, and cannot report more initialized bytes than the destination capacity. Completion errors and immediate call failures resolve the request exactly once. Linux WebKitGTK, Windows WebView2, and macOS WebKit completion bodies, including fallback delivery, are inside an unwind barrier. Caught panic payloads are leaked on that exceptional path so a panicking destructor cannot restart an unwind through the foreign trampoline. Objective-C callback image and error pointers are checked before dereference, and callback captures outlive registration. A native Tauri window pointer is borrowed only while its owning window is live. Process-wide macOS application presentation options use overlapping leases: the first guard preserves the original options, intermediate guard cleanup cannot restore them, and only the final guard restores the preserved state.

**Replacement trigger:** Remove these bridges when Tauri, Wry, WebView2 bindings, or `objc2` provide safe typed operations that preserve asynchronous ownership and main-thread behavior.

**Required validation:** On Linux, Windows, and macOS, cover capture success, immediate failure, callback failure, panic containment including panic-on-drop payloads, webview teardown, and exactly-once completion. On Windows also cover oversized and short COM streams. Exercise native-window setup and teardown on the macOS main thread, including rapid replacement with overlapping presentation guards.

### macOS IOKit power assertions

**Owned module:** The macOS power portion of `apps/client/src-tauri/app/src/pomodoro_enforcement.rs`.

**Contract and disposition:** Pomodoro display and system wake locks use IOKit's [`IOPMAssertionCreateWithName`](https://developer.apple.com/documentation/iokit/1557134-iopmassertioncreatewithname) and paired release API. This boundary is retained because stable Rust and Tauri do not provide equivalent macOS assertion ownership.

**Safety invariants:** External declarations exactly match the C ABI. IOKit's assertion-type macros are represented by live Core Foundation strings rather than nonexistent imported symbols. An assertion identifier is read only after successful creation, owned by one guard, and released once. If the optional system assertion fails after the display assertion succeeds, the guard retains that partial display-only functionality until normal stop. Release failure is reported without reusing the identifier.

**Replacement trigger:** Adopt a maintained safe API when it exposes distinct display and system assertions with explicit creation errors and RAII release.

**Required validation:** On macOS, cover both assertion types, retained display-only behavior when the system assertion fails, repeated start and stop, release failure reporting, and process cleanup.

### Unix hostname

**Owned module:** `apps/client/src-tauri/app/src/chat/terminal.rs`.

**Contract and disposition:** Terminal labels call POSIX [`gethostname`](https://pubs.opengroup.org/onlinepubs/9799919799/functions/gethostname.html) through libc. The fixed writable buffer and return contract are simple, but the call remains unsafe in the binding. This boundary is retained while the standard-library hostname API remains [unstable](https://github.com/rust-lang/rust/issues/135142).

**Safety invariants:** The byte buffer is writable for exactly the length supplied. The return code is checked before reading output. The implementation accepts either a NUL terminator or a completely filled buffer, performs bounded lossy UTF-8 conversion, and rejects empty or control-character identities.

**Replacement trigger:** Use the stable standard-library hostname API when available.

**Required validation:** Cover NUL-terminated, full-length, invalid UTF-8, empty, control-character, and native-call failure results through a testable safe parser or adapter.

### Test-only SQLite statement tracing

**Owned module:** `apps/client/src-tauri/app/src/first_use_contracts.rs`, which is compiled only for tests.

**Contract and disposition:** First-use contract tests install SQLite's [`sqlite3_trace_v2`](https://www.sqlite.org/c3ref/trace_v2.html) callback because SQLx does not expose a safe statement-trace hook for this measurement. The boundary is retained only for deterministic test instrumentation and must not enter production behavior.

**Safety invariants:** SQLx holds the native connection lock while the hook changes. The dedicated in-memory fixture caps its pool at one live connection, performs installation and removal through that sole pooled connection in the normal test flow, and does not expose the registration as a general pool-safe abstraction. On normal completion, the context allocation remains alive until after unregistration and the raw `Arc` reference is balanced exactly once. Cancellation intentionally leaves that strong reference allocated because SQLite may still hold its pointer. This leaks one allocation per canceled test registration, prevents premature release, and is not successful cleanup. The callback checks the event, context, statement, and SQL pointers before borrowing them, copies SQL before the native lifetime ends, synchronizes shared state, ignores a poisoned counter instead of unwinding, and contains every panic before returning across the C ABI. A caught panic payload is intentionally leaked because its destructor may also panic and restart the unwind.

**Replacement trigger:** Replace the FFI hook when SQLx exposes a safe trace callback with explicit registration lifetime and cleanup.

**Required validation:** Run the first-use contract tests with statement classification, install and remove cycles, callback error isolation, pool teardown, and cancellation safety covered. A future owned registration API should replace the intentional cancellation leak and add cancellation-cleanup coverage.

## Removed and narrowed mechanisms

The 2026-08-30 review removed two mechanisms that are not retained boundaries and must not return:

- The Linux tray implementation cast AppIndicator's shared reference to a mutable reference. Upstream guaranteed pointer validity but not unique mutable access, so the cast was unsound. Dynamic icons now use Tauri's safe tray API.
- Windows provider startup zero-initialized `THREADENTRY32` through `unsafe`. The type's safe `Default` implementation plus an explicit `dwSize` assignment now establish initialization and the required input size.

The review also narrowed the Unix workspace boundary. Repeated fixed-form `openat` and descriptor transfers moved into validated wrappers. Raw `dup` and `close` handling moved to `File::try_clone` plus explicit `fdopendir` ownership transfer, and raw `fchmod` calls moved to `File::set_permissions`. `readdir` now distinguishes end of stream from an errno failure. These changes reduce proof duplication without weakening descriptor-relative authorization.

## Change discipline

A change that introduces or materially alters unsafe Rust must include:

1. The safe alternatives considered and the specific missing guarantee that requires the native boundary.
2. A minimal wrapper and concrete local `// SAFETY:` proofs for every operation.
3. Primary contract references and a review of initialization, pointers, sizes, ownership transfer, cleanup, callbacks, threading, and failure sentinels.
4. Focused tests for success, failure, cleanup, and race-sensitive behavior, plus validation on every affected native target.
5. An update to this inventory and its replacement trigger. A proposed new dependency also requires the separate supply-chain review in [Supply chain](supply-chain.md).
