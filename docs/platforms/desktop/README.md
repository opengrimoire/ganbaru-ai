# Desktop platforms

Linux and Windows host the complete local application, including native coding-agent execution, authorized working folders, terminals, Git, desktop media, browser native messaging, and platform-specific Doomscrolling adapters.

The first desktop is the administration device and owns the embedded private-LAN vault coordinator. When no active vault exists, setup starts with a localized welcome screen that presents the free and open-source license summary, a source-code link, the full bundled AGPL 3.0 license in a dialog, and acknowledgments in another dialog. Continuing opens vault selection. If a configured vault is missing or invalid, Continue still leads to vault selection with the recovery error. After initial vault selection, a dedicated linking screen immediately shows a short-lived phone pairing QR invitation. **Not now** completes onboarding for the current vault without linking, so closing or reloading the app opens the main app. Closing the linking screen before choosing either action leaves onboarding unfinished and shows it again at the next launch. Data settings can create further invitations. Phones scan the QR in Ganbaru AI, while another desktop copies the complete pairing code from the coordinator and pastes it into its own Data settings. The code-entry dialog points users to Settings > Data on the coordinating computer and keeps invalid or expired code guidance inside the dialog. A desktop enrolled this way becomes a client and stops its own coordinator. A linked-device control immediately after Pomodoro lists devices and opens handoff actions without adding a permanent read-only warning row to the shell. The coordinator has no general remote command, SQL, or arbitrary file interface. It runs only with the administration desktop and supports a bounded membership for one vault.

On Linux, the linking screen detects active UFW and firewalld configurations. The development build disables the firewall permission button on the onboarding screen and explains that its executable cannot use the installed trusted helper. Packaged builds offer the permission action. Before Linux requests administrator authentication, Ganbaru AI explains why access is needed and states that the application never receives the password. Debian and RPM packages install a named PolicyKit action backed by the root-owned Ganbaru AI executable. Development and portable builds use the operating system's generic command authorization fallback because their executable cannot safely act as a privileged helper. Ganbaru AI limits its production rule to TCP port 43821 on the current private subnet, interface, and local address. The separately identified development application uses TCP 43822 so it can run beside production. The application records only rules it created and provides a removal action in Data settings. The coordinator still accepts only the mutually authenticated, bounded handoff protocol, and it listens only while Ganbaru AI is running. Unsupported firewall managers remain a truthful manual-action state.

When another device owns the vault, desktop keeps its last complete copy available read-only. Opening that copy presents the current main-device state and asks whether to switch control here or continue read-only. The same prompt appears immediately when a completed handoff makes the open desktop copy read-only. `Switch to this device` requests the current owner snapshot through the coordinator and advances ownership only after staging and validation. Reachable clients keep a bounded authenticated coordinator poll active so refresh and ownership requests begin promptly. The slower reconnect interval remains the offline fallback. Desktop browser and application Doomscrolling usage continues in a bounded device-local spool and joins the owner's combined counter when the LAN connection is available. The toolbar control uses a stable status indicator for queued work; only an explicitly running foreground action shows continuous progress animation.

Linking does not merge independently created vaults. Before a first linked-vault activation replaces desktop data, Ganbaru AI requires explicit confirmation and preserves the previous vault in a visible sibling folder beside the selected Ganbaru AI folder. Invitations and later transfers verify both the handoff protocol and the exact embedded database migration fingerprint before snapshot preparation. Incompatible installations ask the user to update Ganbaru AI on both devices, and final staging validation still verifies SQLite migration history and checksums.
