# Desktop platforms

Linux and Windows host the complete local application, including native coding-agent execution, authorized working folders, terminals, Git, desktop media, browser native messaging, and platform-specific Doomscrolling adapters.

The desktop process also owns the embedded private-LAN vault coordinator. After initial vault selection, a dedicated linking screen immediately shows a short-lived Android pairing QR invitation. **Not now** defers linking for the current app session, but closing or reloading the app returns to the linking screen until the user completes it explicitly. A linked-device control immediately after Pomodoro opens the device status and handoff actions without adding a permanent read-only warning row to the shell. Data settings remains the fallback for linking later. The coordinator has no general remote command, SQL, or arbitrary file interface. It runs only with the desktop application and supports one enrolled Android phone and one vault.

On Linux, the linking screen detects active UFW and firewalld configurations. Before Linux requests administrator authentication, Ganbaru AI explains why access is needed and states that the application never receives the password. Debian and RPM packages install a named PolicyKit action backed by the root-owned Ganbaru AI executable. Development and portable builds use the operating system's generic command authorization fallback because their executable cannot safely act as a privileged helper. Ganbaru AI limits its rule to TCP port 43821 on the current private subnet, interface, and local address, records only rules it created, and provides a removal action in Data settings. The coordinator still accepts only the mutually authenticated, bounded handoff protocol, and it listens only while Ganbaru AI is running. Unsupported firewall managers remain a truthful manual-action state.

When Android owns the vault, desktop keeps its last complete copy available read-only. Opening that copy presents the current main device and asks whether to switch control here or continue read-only. The same prompt appears immediately when a completed handoff makes the open desktop copy read-only. `Use on this device` requests the current Android snapshot through the coordinator and advances ownership only after staging and validation. While both applications are reachable, Android keeps a bounded authenticated coordinator poll active so foreground refresh and ownership requests begin promptly. The slower reconnect interval remains the offline fallback. Desktop browser and application Doomscrolling usage continues in a bounded device-local spool and joins the owner's combined counter when the LAN connection is available. The toolbar control uses a stable status indicator for queued work; only an explicitly running foreground action shows continuous progress animation.
